# M5 계획: 긴 연재 대응 (검사 입력 상한)

M5는 **화가 수백 개로 늘어도 [이 화 검사]의 입력이 일정 크기 안에 머물게 하고, 그래도 탐지 품질이 떨어지지 않는지 재는** 단계다.

- 배경: [M4 결과](M4-REPORT.md)의 가장 큰 한계. 앞 화 사실이 화마다 약 11개씩 늘어 15화에서 163개, 입력 10,223토큰이었다. 이대로면 300화에서 입력이 20만 토큰 안팎이 된다. ADR 0001의 남은 질문("장편 규모는 측정하지 않았다")도 같은 문제다.
- 확정한 선택 (2026-10-25, 사용자)
  - 긴 원고: M0-A 15화 사이에 설정집에 맞는 중간 화를 luna로 만들어 끼워 넣는다. 정답 오류 30개는 그대로 쓰고, 오류와 근거 사이 거리만 길어진다
  - 규모: 150화
  - 이번 단계 OpenAI 비용 한도: $2

## 1. 범위

**포함**

- **긴 시험 원고 (150화)**
  - M0-A 원래 화 k를 150화 중 `10k − 9`번째(1, 11, 21, …, 141)에 둔다. 원래 화 사이에 9개씩, 15화 뒤에 9개, 모두 중간 화 135개를 만든다.
  - 중간 화는 설정집(`world-bible.md`)과 플롯(`plot.md`)을 따르는 일상·사건 장면이다. 앞뒤 원래 화의 날짜 사이에 놓인다. 화당 약 2,500~3,500자로, M0-A 화(약 1,200자)보다 실제 연재 화에 가깝다.
  - 중간 화에는 의도적인 오류를 넣지 않는다. 정답표는 M0-A 정답표의 화 번호만 바꿔 쓴다.
  - 결과(150화 원고, 바꾼 정답표, 생성 기록)는 `spikes/m5-scale/benchmark/`에 남긴다.
- **입력 상한 전략 비교**: 앞 화 사실을 고르는 방법(core `candidateFacts`)을 몇 가지로 나눠, 같은 150화 원고에서 비교한다.
  - S0 전부: 지금 방식 (기준선)
  - S1 첫 값과 최신 값: 같은 인물·같은 속성의 사실이 여러 화에 있으면 처음 나온 것과 가장 최근 것만 남긴다
  - S2 예산 안에서 최근 우선: 사실 수 상한(예: 400개) 안에서 최근 화부터 채운다. 다만 인물·속성마다 첫 값은 남긴다
  - S1과 S2를 합친 것
  - 속성 이름은 모델이 자유롭게 써서("나이", "나이(2008)") 같은 속성을 모으는 규칙은 단순하게 시작하고, 측정으로 판단한다.
- **측정**: 150화 원고를 모두 분석(luna)한 뒤, 원래 화 14개(11, 21, …, 141번째)를 전략마다 검사해 M0-A 채점기로 채점한다. 중간 화는 검사 대상이 아니다 (정답이 없다).
- **제품 적용**: 측정에서 고른 전략을 [이 화 검사]에 넣는다. 패널에 "앞 화 사실 N개 중 M개와 비교"를 보여 주고, 예상 비용도 상한을 적용한 입력으로 계산한다.

**제외**: 설치 파일, [전체 검사], echo 차단, 실제 원고 확인, 검색 기반 근거 찾기(M0-A A·D 전략), 임베딩.

## 2. 측정 도구

- **키 다루기**: AI를 부르는 측정 스크립트(중간 화 생성, 분석, 검사)는 Electron으로 실행해 앱이 `safeStorage`로 저장한 키를 읽는다. 키를 환경 변수, 파일, 명령줄에 두지 않는다. 앱과 같은 사용자 데이터 폴더를 써야 하므로 구현 첫 단계에서 동작을 확인한다.
- **분석·검사**: 제품의 `analyzeChapters`, `checkChapter`를 그대로 쓴다. 전략만 바꿔 검사한다.
- **생성 기록**: 중간 화마다 프롬프트 버전, 모델, 사용량, 비용을 남긴다.
- **채점**: M0-A 채점기에 정답표·원고 폴더를 고를 수 있는 인자를 더한다. 채점 규칙은 바꾸지 않는다.
- **생성 화 검수**: 원래 화를 검사했는데 정답표에 없는 결과(review queue)가 나오면, 근거가 중간 화인지 보고 사람이 판단한다. 중간 화가 새 모순을 만들었으면 그 결과는 따로 세고 보고서에 적는다.

## 3. 성공 기준

| 항목 | 기준 |
|---|---|
| 입력 상한 | 고른 전략으로 150화 위치(원래 15화)의 검사 입력 ≤ 30,000토큰. 사실 수가 화 수와 무관하게 상한 안에 머문다 (300화로 외삽) |
| 품질 유지 (150화, test) | 고른 전략의 Recall이 S0보다 10%p 이상 낮지 않다. 화당 FP ≤ 0.3, 함정 오탐 ≤ 1개 |
| 비용·시간 (luna) | 고른 전략으로 검사 한 번 ≤ $0.005, < 30초 |
| 제품 | 패널에 넘긴 사실 수와 전체 수가 보인다. 예상 비용이 상한을 반영한다. 기존 단위 테스트·E2E 통과 |
| 비용 한도 | 이번 단계 OpenAI 비용 합계 ≤ $2 |

- S0의 150화 결과도 기록한다. 원고가 길어지는 것만으로 품질이 변하는지(M4 15화 결과와 비교) 보는 자료다.
- 측정은 전략마다 1회다. 차이가 반복 편차(M0-A luna 10%p)보다 작으면 "차이 없음"으로 본다.

## 7. 위험

- **중간 화가 새 모순을 만든다**: luna가 설정집과 다른 내용을 쓸 수 있다. 원래 화만 검사하고, 정답표에 없는 결과는 근거 화를 보고 따로 센다.
- **근거가 중간 화에서 나온다**: 중간 화가 설정을 다시 말하면, 모델이 원래 근거 화 대신 더 가까운 중간 화를 근거로 들 수 있다. M0-A 채점기의 "근거 화 정확도"는 낮아질 수 있으나 탐지(TP) 판정에는 영향이 없다. 보고서에서 따로 본다.
- **합성 원고의 한계**: 중간 화도 생성한 글이라 실제 연재보다 균질하다. 실제 원고 확인은 다음 단계로 남는다.
- **속성 이름이 제각각이다**: S1의 "같은 속성"을 묶지 못하면 상한 효과가 작다. 그 경우 S2(예산)가 상한을 보장한다.
