# M1 결과: Electron 셸 + 에디터 + Markdown 저장

- 날짜: 2026-10-24
- 계획: [`M1-PLAN.md`](M1-PLAN.md)
- PR: #10 (골격), #14 (원고 형식 core), #15 (파일 입출력·IPC), #16 (화면·자동 저장), #17 (바깥 변경·강제 종료·성능)

## 결론

**M1 성공 기준을 모두 충족했다.** 원고 폴더를 열고, 화 목록을 보고, 한 화를 편집하면 자동으로 저장되는 최소 집필 앱이 동작한다. 원고 파일은 고친 줄 말고는 바이트 단위로 그대로다.

| 기준 (M1-PLAN 5절) | 결과 | 확인 방법 |
|---|---|---|
| 원고 보존: 코퍼스 byte 동일·멱등·국소성 100% | 49/49 사례 모두 통과 | 단위 테스트 (M0-B 코퍼스 + M0-A 15화) |
| 열기만 하고 닫기: 파일 바이트 변화 0 | 15화 중 4화를 모두 열어 보고 닫음, 변화 0 (BOM·CRLF·frontmatter 원고 포함) | E2E |
| 자동 저장: 입력 후 3초 안 | 약 2.5초 (1.5초 대기 + 저장) | E2E |
| 강제 종료: 잃는 것은 마지막 저장 이후 분량뿐 | 마지막 자동 저장은 그대로, 저장 전 입력만 사라짐, 반쯤 쓰인 파일·임시 파일 없음 | E2E (프로세스 트리 강제 종료) |
| 외부 변경을 덮어쓰지 않음 | 저장 안 된 변경이 있으면 멈추고 묻고, 없으면 다시 불러옴 | E2E |
| 성능: 2만 자 열기 < 1초 | 85ms (5회 중앙값, 상한) | `pnpm perf` |
| 성능: 입력 지연 p95 < 50ms | 6.1ms (2만 자, 문서 중간) | `pnpm perf` |
| 시작: 300화 목록 < 1초 | 305ms (상한) | `pnpm perf` |
| IME 핵심 시나리오 1·2·3·9·11 | 모두 통과 (MS 한국어 IME) | 사용자 수동 확인 |

테스트: 단위 38개, E2E 11개. 성능은 Ryzen 9 3900X 한 대에서 쟀다.

## 만든 것

- **원고 형식** (`src/core/manuscript`, ADR 0002): C3(한 줄 = 한 문단) 변환기
  - BOM, 줄바꿈, frontmatter, 마지막 개행은 에디터 밖에서 지킨다.
  - 저장 전에 직렬화한 결과를 다시 읽어 검사한다. 글자가 사라지면 저장하지 않고, 다시 열 때 모양만 달라지면 저장한 뒤 그 줄을 알린다.
- **화 파일 규칙** (`src/core/project`)
  - 화 순서는 파일 이름 앞 번호로 정한다. 새 화는 `016.md`처럼 다음 번호로 만든다.
  - frontmatter는 최상위 `key: value`만 읽는다. 중복 id는 감지만 한다.
- **파일 입출력** (`src/main`)
  - 원자적 쓰기: 임시 파일에 쓰고 fsync한 뒤 이름을 바꾼다. Windows 파일 잠금에 대비해 재시도한다.
  - 쓰기 직전 해시를 비교해 덮어쓰기를 방지한다.
  - UTF-8이 아닌 파일은 열지 않는다.
  - `chapters/` 폴더를 감시한다.
- **화면** (`src/renderer`)
  - 화 목록, TipTap 에디터, 상태 표시줄
  - 자동 저장(1.5초), 그리고 화 이동·포커스 잃음·Ctrl+S·종료 시 즉시 저장
  - 충돌 안내, 다시 불러옴 알림
- **보안 기본값**
  - 모든 renderer를 sandbox로 실행한다. 컨텍스트 격리를 켜고 Node 통합을 끈다.
  - CSP를 적용하고, 새 창과 외부 탐색을 차단한다.
  - renderer는 `chapters/` 안의 파일 이름으로만 파일을 요청한다.

## M1 중에 정한 것 (DECISIONS)

- 작가가 입력한 `*`가 다시 열 때 강조로 읽히는 경우, 친 그대로 저장하고 경고한다.
- Shift+Enter는 새 문단이다. 인용 안에는 문단만 둔다.
- 붙여넣기는 서식을 지우고 글자만 넣는다. 바깥에서 끌어다 놓기는 받지 않는다.
- id는 새로 만드는 화에만 넣는다. 중복 id는 경고만 하고 재발급은 M2에서 정한다.

## 진행 중 문제와 교훈

- **쌓아 올린 PR이 main에 들어가지 않음**: #11~#13을 앞 PR 브랜치를 기준으로 열었는데, 기준을 main으로 바꾸기 전에 병합되어 각 브랜치로 들어갔다. 같은 커밋을 main 기준으로 다시 올렸다(#14~#16). 이후로 PR은 항상 main 기준으로 하나씩 연다.
- **강제 종료 테스트가 잘못 통과함**: 처음에는 감싸는 프로세스만 죽여서, 살아남은 앱이 자동 저장까지 했다. Windows에서 프로세스 트리 전체를 끝내도록 고쳤다.
- **글자 손실 검사 오류**: 이모지 같은 서로게이트 쌍을 잘못 세서 멀쩡한 원고를 "손실"로 판정했다. 코퍼스 테스트에서 잡았다.
- **E2E 격리**: E2E가 사용자의 실제 설정(마지막 연 폴더)을 건드리지 않도록 `--user-data-dir`로 임시 폴더를 쓴다.

## 한계와 다음으로 넘기는 것

- Windows 데스크톱 한 대에서만 확인했다. 저사양 노트북, macOS·Linux, MS 한국어 IME 외 입력기는 확인하지 않았다.
- 설치 파일(패키징)은 만들지 않았다. 지금은 `pnpm dev`로만 실행한다.
- 네트워크 드라이브와 OneDrive 폴더에서 감시·원자적 쓰기가 어떻게 동작하는지는 시험하지 않았다.
- 범위 밖으로 둔 것: 화 이름 바꾸기·삭제·순서 변경, 검색, 글자 수, 설정 화면.
- 줄바꿈이 섞인 파일을 LF로 통일해 저장할 때 사용자에게 알리지 않는다.
- 다음 단계는 M2(SQLite 인덱스·검색)다. 여기서 중복 id 재발급과 한국어 검색(ADR 0001: trigram만으로는 2글자 이름 검색 불가)을 함께 다룬다.
