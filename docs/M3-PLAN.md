# M3 계획: OpenAI 연결과 화별 사실 추출

M3는 **작가가 버튼을 누르면 화마다 인물과 사실을 원문 인용과 함께 뽑아 저장**하는 단계다. M4(연속성 오류 탐지)가 이 결과를 쓴다. AI 없이도 앱은 지금처럼 동작해야 한다.

- 근거: [ADR 0001](decisions/0001-continuity-detection-strategy.md) (B 전략: Fact + 원문 인용, 인용문 존재 검사 필수), VISION §11~§14 (BYOK, API 키 보안, AI는 필수가 아님), [M2 결과](M2-REPORT.md)
- 확정한 선택 (2026-10-25, 사용자)
  - 범위: API 키 설정과 화별 사실 추출·저장까지. 탐지는 M4
  - 실행 시점: 작가가 버튼으로 실행한다. 전체 분석 전에 예상 비용을 보여 주고 확인받는다
  - 기본 모델: `gpt-6-luna`. 설정에서 `gpt-6.1-sol`로 바꿀 수 있다
  - 결과 저장: 원고 폴더의 `.loreweave/ai.db`. 검색 색인과 분리하고, 번호 붙은 마이그레이션을 쓴다

## 1. 범위

**포함**

- **설정 화면**: API 키 입력·삭제, 모델 선택, [연결 확인] 버튼, 지금까지 쓴 비용
- **API 키 보안**
  - Electron `safeStorage`로 암호화해 사용자 데이터 폴더에 둔다 (Windows에서는 DPAPI).
  - 키는 main 프로세스만 읽는다. renderer는 "설정됨" 여부만 안다.
  - 프로젝트 폴더와 로그에는 남기지 않는다.
- **분석 실행**
  - [이 화 분석], [바뀐 화 모두 분석] 버튼을 둔다.
  - 여러 화를 분석할 때는 먼저 예상 비용(상한)을 보여 주고 확인을 받는다.
  - 진행률과 [취소]를 보여 준다. 끝난 화의 결과는 취소해도 남긴다.
- **처음 분석할 때 알림**: "이 화의 본문이 OpenAI로 전송됩니다"를 한 번 확인받는다 (local-first 원칙).
- **추출**: 화마다 요약, 등장 인물·조직·장소(별칭 포함), 사실(`entity | predicate | value | quote`)을 뽑는다.
- **인용문 존재 검사** (ADR 0001 결정 2): 모델이 낸 `quote`를 본문에서 찾는다.
  - 찾으면 줄 주소(M2)와 함께 저장한다.
  - 못 찾으면 버리고 버린 개수를 기록한다.
- **분석 상태 표시**: 화 목록에 미분석 / 분석됨 / 분석 후 바뀜(본문 해시가 다름)을 표시한다.
- **사실 패널**: 오른쪽 패널에 현재 화에서 뽑은 사실을 보여 준다. 인용을 누르면 그 줄로 이동한다 (M2 이동 재사용, M4 "근거로 이동"의 예행연습).

**제외 (M4 이후)**: 연속성 오류 탐지, 다른 화와 비교, 사실 직접 편집·승인, 인물 사전 화면, 자동 분석, 다른 AI 제공자, 로컬 LLM.

## 2. 구조

| 위치 | 내용 |
|---|---|
| `src/core/ai/` | 추출 결과 형식과 검증, 인용 위치 찾기, 예상 비용 계산, 프롬프트. Electron·OpenAI SDK와 무관하다 |
| `src/main/secrets.ts` | `safeStorage`로 키를 저장하고 읽는다. 키를 다루는 곳은 여기와 AI 클라이언트뿐이다 |
| `src/main/ai-client.ts` | OpenAI 호출 (Responses API + Structured Outputs). 재시도, 시간 제한, 취소, 사용량·비용 기록 |
| `src/main/ai-db.ts` | `.loreweave/ai.db`와 번호 붙은 마이그레이션 (`migrations/001_*.sql` …) |
| `src/main/analyzer.ts` | 분석 대기열: 한 번에 한 화, 취소, 본문 해시로 바뀐 화 판단 |
| `src/renderer/` | 설정 화면, 분석 버튼·확인·진행률, 사실 패널 |

- **추출 프롬프트**: M0-A에서 검증한 문구(`extract` 프롬프트, 해시 `fa2971c6f7e8`)를 그대로 옮긴다. 출처는 태그 `spike-m0a-2026-10-24`다. 문구를 바꾸면 버전을 올리고, 분석 결과에 프롬프트 버전을 함께 저장한다.
- **분석 입력**: 화면에 보이는 본문 줄(M2 `visibleLines`)이다. frontmatter와 강조 기호는 빼고, 인용 위치를 같은 줄 기준으로 찾는다.
- **화 구분**: 화는 파일 이름으로 구분한다 (M2 결정: id가 없는 기존 화는 건드리지 않음). 파일 이름이 바뀌면 그 화는 미분석으로 보인다. 이름 바꾸기 기능이 생길 때 다시 본다.

## 3. 저장 (`ai.db`)

다시 만들려면 비용이 드는 정보라, 검색 색인과 규칙이 다르다.

- **마이그레이션**: 번호 붙은 SQL 마이그레이션을 쓴다. 형식을 바꿔도 기존 결과를 지우지 않는다. `PRAGMA user_version`으로 적용 단계를 기록한다.
- **안전 설정**: WAL + `synchronous = FULL`로 둔다 (색인과 달리 다시 만들 수 없다).
- **깨진 파일**: 지우지 않고 `ai.db.broken-<시각>`으로 이름을 바꿔 둔 뒤 새로 만들고 알린다.
- **표 (초안)**
  - `analyses(file, content_hash, model, prompt_version, summary, input_tokens, output_tokens, cost_usd, dropped_quotes, created_at)`
  - `entities(analysis_id, name, aliases)`
  - `facts(analysis_id, entity, predicate, value, quote, line, start, end)`
- 같은 화를 다시 분석하면 그 화의 이전 결과를 바꾼다. 이력은 M3에서 두지 않는다.

## 4. 비용과 실패

- **비용 계산**: 호출마다 사용량(입력·캐시·출력 토큰)으로 비용을 계산해 기록한다.
  - 단가는 모델별 설정값으로 두고 문서 날짜를 함께 적는다. M0-A에서 캐시 쓰기를 이중으로 계산한 실수가 있었으므로 그 경우를 테스트로 막는다.
- **예상 비용**: 본문 글자 수로 계산한 상한을 보여 준다. 실제 비용은 분석이 끝난 뒤 보여 준다.
- **실패 처리**
  - 잘못된 키(401): 분석을 멈추고 설정으로 안내한다.
  - 한도 초과(429)와 네트워크 오류: 짧게 재시도한다.
  - 시간 초과: 그 화만 실패로 남기고 다음 화로 넘어간다.
  - 출력 형식 오류: 저장하지 않는다.

## 5. 성공 기준

| 항목 | 기준 |
|---|---|
| 키 보안 | 키가 디스크에 평문으로 없다 (설정 파일과 프로젝트 폴더 검사). renderer에서 키를 읽을 수 없다 (E2E) |
| AI 없이 동작 | 키가 없거나 네트워크가 없어도 M1·M2 기능과 E2E가 그대로 통과한다 |
| 인용문 존재 검사 | 본문에 없는 인용을 가진 사실은 저장되지 않는다 (단위 테스트, 가짜 응답) |
| 실제 추출 (M0-A 15화, luna) | 인용이 본문에서 찾아지는 사실 비율 ≥ 90%, 화당 비용 ≤ $0.005, 15화 전체 < 3분 |
| 사실에서 이동 | 사실의 인용을 누르면 선택된 글자가 인용과 같다 (E2E, 저장된 결과로) |
| 원고 보존 | 분석이 화 파일을 바꾸지 않는다 |
| 결과 보존 | 마이그레이션을 적용해도 기존 분석 결과가 남는다. 깨진 `ai.db`는 지우지 않고 옮긴다 |
| 바뀐 화 판단 | 분석 뒤 본문이 바뀐 화만 "바뀜"으로 표시되고, [바뀐 화 모두 분석]이 그 화만 보낸다 |
| 취소 | 진행 중 취소하면 다음 화를 보내지 않고, 끝난 화의 결과는 남는다 |

실제 API 호출 테스트는 비용이 들므로 자동 테스트에 넣지 않는다. 사용자의 키로 한 번 실행하는 스크립트로 둔다. 예상 비용은 15화 × luna 약 $0.03이다.

## 6. 진행 순서 (PR은 main 기준으로 하나씩)

1. **core/ai**: 추출 형식 검증, 인용 위치 찾기, 비용 계산(캐시 쓰기 포함), 예상 비용, 프롬프트
2. **main/연결**: `safeStorage` 키 저장, OpenAI 클라이언트, 설정·연결 확인 IPC, 사용량 기록
3. **main/분석**: `ai.db`와 마이그레이션, 분석 대기열(취소, 바뀐 화), 가짜 클라이언트로 테스트
4. **renderer**: 설정 화면, 분석 버튼·예상 비용 확인·진행률·취소, 화 목록 상태, 사실 패널과 이동
5. **실제 실행과 결과 문서**: 사용자 키로 M0-A 15화를 추출해 기준을 확인한다

## 7. 추가할 라이브러리

| 패키지 | 이유 |
|---|---|
| `openai` | 공식 SDK. Responses API와 Structured Outputs, 재시도, 시간 제한, 취소(`AbortSignal`)를 직접 만들지 않는다. M0-A에서 같은 SDK(7.43)로 569회 호출을 검증했다 |

## 8. 위험

- **원고가 외부로 전송된다**: 처음 한 번 알리고, 작가가 버튼을 누를 때만 보낸다. 자동 분석은 하지 않는다.
- **모델이 인용을 바꿔 쓴다**: 인용문 존재 검사로 버린다. 버린 비율이 높으면 결과 화면에 표시한다.
- **비용이 예상을 넘는다**: 예상 비용은 상한으로 계산하고, 실제 비용을 누적해 보여 준다.
- **`safeStorage`를 쓸 수 없는 환경** (일부 Linux): 키를 저장하지 않고 이번 실행 동안만 쓰도록 안내한다. Windows에서는 DPAPI를 쓴다.
- **모델 이름과 단가가 바뀐다**: 설정값으로 두고, 단가에는 확인한 날짜를 적는다.
