# M6 계획: 실제 장편으로 확인

M6는 **합성 원고가 아닌 실제 장편에서 분석과 [이 화 검사]가 어떻게 동작하는지 보는** 단계다. 지금까지의 측정(M0-A, M4, M5)은 모두 합성 원고였다. ADR 0001의 남은 질문("실제 원고로 소량 sanity check")에 답한다.

- 원고: 작가가 구한 실제 장편 한 편, 12권 (저장소 밖 `D:\LoreWeave-test\` 아래 폴더, `.txt`, CP949, 공백 뺀 약 107만 자). 작품 이름은 문서와 PR에 적지 않는다. 게임 판타지라 레벨·능력치처럼 정당하게 계속 바뀌는 숫자가 많다. 정상적인 변화를 오류로 보는지(오탐) 보기 좋은 원고다.
- 확정한 선택 (2026-10-25, 사용자)
  - 화 나누기: 약 5,000자씩, 빈 줄·장면 경계에서 끊는다 (약 210화)
  - 검사: 전체를 분석하고, 고르게 퍼진 20화만 검사한다
  - `.txt` 변환은 측정용 스크립트로만 한다. 앱의 가져오기 기능은 측정 결과를 보고 따로 정한다

## 1. 원고 다루기 (저작권)

- 상업 출판된 소설이다. **원고와 원고에서 나온 결과는 저장소에 넣지 않는다.**
  - 변환한 화 파일과 `ai.db`는 저장소 밖(`D:\LoreWeave-test\`)에 둔다.
  - 인용이 들어간 검사 결과와 판정표도 저장소 밖에 둔다.
- 저장소에 남기는 것: 스크립트, 집계 숫자(사실 수, 결과 수, 판정별 개수, 비용, 시간), 종류별 경향. 보고서에는 원문 인용을 넣지 않고 내용을 풀어 쓴다.
- 분석과 검사는 원고 본문을 OpenAI로 보낸다. 작가가 정한 일이고, 실행 전에 비용과 함께 한 번 더 확인받는다.

## 2. 범위

**포함**

- **변환 스크립트** (`scripts/import-txt.ts`)
  - CP949(EUC-KR)를 UTF-8로 바꾼다. Node 내장 `TextDecoder('euc-kr')`를 쓰므로 새 라이브러리는 없다.
  - 권 순서대로 이어 약 5,000자마다 끊는다. 끊는 곳은 빈 줄 → 장면 구분 줄 → 문단 끝 순서로 고른다.
  - 화 파일은 `# N화` 제목 줄과 원문 줄이다. 원문 한 줄을 한 문단으로 둔다.
  - 원고 형식(C3)에서 제목·인용·강조로 읽힐 기호(줄 앞의 `#`, `>`, 줄 안의 `*`)는 비슷한 전각 기호로 바꾼다. 원문 글자가 보이는 줄에서 빠지지 않게 하려는 것이다.
  - 변환 전후 글자 수(공백 제외)를 비교해 빠진 글자가 없는지 확인한다.
- **측정 스크립트** (`scripts/measure-real.ts`, Electron으로 저장된 키 사용, 비용 한도)
  - 모든 화를 분석한다 (M3).
  - 2화부터 마지막 화까지 고르게 퍼진 20화를 제품과 같은 설정으로 검사한다 (M4, M5의 400개씩 나눠 검사).
  - 검사 결과를 판정용 표(인용·근거·설명)로 저장소 밖에 쓴다.
- **판정**: 정답표가 없어 결과마다 사람이 판단한다.
  - 판정 종류
    - **맞는 지적**: 원고에 실제로 앞뒤가 안 맞는 곳이 있다
    - **정당한 변화**: 레벨업, 시간 경과, 거짓말, 회상 등 원고가 설명하는 변화
    - **잘못 읽음**: 문맥·주어를 잘못 이해했거나 근거가 맞지 않는다
    - **판단 어려움**
  - 1차로 내가 원문과 근거를 읽고 판정한다. 작가가 그중 10개 이상을 골라 확인하고, 판정이 다르면 작가 판정을 따른다.

**제외**: 재현율(정답표가 없다), 앱의 텍스트 가져오기 기능, 프롬프트 수정, 여러 번 반복 측정.

## 3. 성공 기준 (실행 전에 고정)

| 항목 | 기준 | 근거 |
|---|---|---|
| 추출 인용 보존 | 인용이 원문에서 찾아지는 사실 ≥ 90% | M3 기준과 같다 (합성 원고 99%) |
| 검사 Precision (사람 판정) | 맞는 지적 / 전체 결과 ≥ 50% | M0-PLAN의 최소 기준과 같다. 실제 원고는 합성보다 어렵다 |
| 화당 오탐 | (정당한 변화 + 잘못 읽음) / 검사한 화 ≤ 1 | M0-PLAN 기준과 같다. 작가가 경고를 무시하게 되는 선 (INTENT §18) |
| 근거 | 보여 준 결과의 문장과 근거가 모두 원고에 있다 | M4와 같다 |
| 비용 | 이번 단계 합계 ≤ $1.5 | 예상 약 $0.8 |

- 기준을 넘지 못해도 단계는 끝낸다. 무엇이 오탐을 만드는지(종류별·원인별)를 보고서에 남기고, 다음 단계(프롬프트, 사실 정리, 화면)의 근거로 쓴다.
- 함께 기록할 것
  - 화당 사실 수와 사실 수 증가 (실제 화 길이에서)
  - 검사 한 번의 비용·시간·나눈 횟수
  - 종류별 결과 수

## 7. 위험

- **오탐이 많을 수 있다**: 게임 판타지의 레벨·능력치·아이템은 계속 바뀐다. 탐지 프롬프트는 시간에 따른 자연스러운 변화를 오류로 보지 말라고 하지만, 합성 원고에서만 확인했다. 이번 측정의 주목적이 이것을 보는 것이다.
- **화 경계가 장면 중간일 수 있다**: 글자 수로 끊어서 한 장면이 두 화로 나뉠 수 있다. 사실 추출과 검사는 화 단위라 영향이 있을 수 있다. 보고서에 적는다.
- **원문에 작가 후기·수정 알림이 섞여 있다** (예: "4화 수정했습니다"). 이야기 밖의 글이 사실로 뽑힐 수 있다. 지우지 않고 그대로 두고, 결과에 나타나면 따로 센다.
- **판정이 주관적이다**: 1차 판정은 내가 하고 작가가 일부를 확인한다. 판정 기준과 애매한 사례를 보고서에 적는다.
