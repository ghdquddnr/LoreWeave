# Windows 시험자용 시작 안내 (폴더 실행본)

전달받은 LoreWeave **Windows x64 폴더 실행본**을 처음 시험하는 사람을 위한 안내입니다. 미서명 폴더 실행본이며 **설치 프로그램도, 공개 배포본도 아닙니다.** 출시 준비가 끝났다는 뜻이 아니고, 아래 [검증 현황](#검증-현황)에 적은 범위만 확인했습니다.

시험자는 `pnpm`, 개발 서버, 소스 저장소가 필요하지 않습니다. 실행본을 만드는 일은 개발자의 준비 단계입니다([개발자 참고](#개발자-참고)).

## 1. 받은 폴더

- 폴더 **전체**를 그대로 두고 실행하세요. 실행 파일 하나만 다른 곳으로 옮기면 동작하지 않습니다.
- 실행 파일 이름은 빌드에 따라 둘 중 하나입니다.

  | 폴더 | 실행 파일 | 비고 |
  | --- | --- | --- |
  | 기본 빌드 | `electron.exe` | 이름·아이콘이 Electron 그대로입니다. 이 안내의 검증 대부분(ZIP 풀기, §3 시작, 자동·수동 관측)은 이 빌드 기준입니다 |
  | 선택형 브랜드 빌드 | `LoreWeave.exe` | 이름·아이콘·정보만 바뀐 빌드. **기본 빌드의 관측을 이 빌드에 그대로 적용하지 마세요.** 이 빌드에서 확인한 것은 검증 현황 표의 "선택형 `LoreWeave.exe` 첫 실행" 한 가지뿐입니다 |

- Windows가 미서명 실행 파일에 경고를 보일 수 있습니다(SmartScreen 동작은 확인하지 못했습니다). 출처를 아는 폴더만 실행하세요.

### ZIP으로 받았다면: 먼저 전체를 풀어 주세요

ZIP 안에 보이는 `electron.exe`를 바로 열거나, 그 파일 하나만 꺼내 옮기지 마세요. 실행에는 같은 폴더의 다른 파일이 모두 필요합니다.

1. ZIP **전체**를 아직 없는 새 폴더에 풉니다. Windows PowerShell 5.1 예시(`<…>` 두 곳만 실제 경로로 바꿉니다. 경로 안의 작은따옴표는 §3처럼 `''`로 씁니다):

   ```powershell
   $ErrorActionPreference = 'Stop'
   $zip  = '<받은 ZIP 파일 경로>'
   $dest = '<새 압축 해제 폴더 경로>'     # 아직 없는 새 경로
   if (-not (Test-Path -LiteralPath $zip)) { throw "ZIP이 없습니다: $zip" }
   if (Test-Path -LiteralPath $dest) { throw "이미 있는 경로입니다. 다른 새 경로를 쓰세요: $dest" }
   Expand-Archive -LiteralPath $zip -DestinationPath $dest
   ```

   **파일 탐색기로 풀기(선택):** 탐색기에서 ZIP을 열었을 때 Windows 기본 압축 풀기(압축 폴더 도구의 [압축 풀기] 또는 모두 풀기 마법사)가 보이면 그것으로 ZIP **전체**를 아직 없는(또는 비어 있는) 새 폴더에 풀어도 됩니다. 마우스 오른쪽 메뉴에 풀기 항목이 없거나 ZIP이 다른 압축 프로그램으로 열리면 위 PowerShell 방법을 쓰세요.

2. 풀면 목적지(위 `$dest` 또는 탐색기에서 고른 새 폴더) 아래에 폴더가 하나 생깁니다(확인한 ZIP에서는 `app`). **`electron.exe`(또는 `LoreWeave.exe`)가 바로 들어 있는 그 폴더**가 §3의 `$app`입니다. 그 폴더 안의 파일은 하나도 빼거나 옮기지 말고 그대로 두세요.
3. 이어서 [§3](#3-새-격리-폴더로-시작하기-powershell-예시)의 예시로 새 격리 프로필(`--user-data-dir`)과 합성 원고로 시작합니다. 풀기만 하고 `--user-data-dir` 없이 실행하지 마세요.

**확인한 범위:** 한 PC에서, 같은 Windows PowerShell 5.1의 `Compress-Archive`로 만든 ZIP을 `Expand-Archive`로 한글·공백·괄호가 든 경로에 풀었을 때 파일 4,635개의 상대 경로·크기·SHA-256이 원본과 모두 일치했고, 풀린 폴더를 §3의 블록(경로 두 곳만 치환)으로 시작해 환영 화면과 합성 원고 열기까지 확인했습니다. 위 코드의 존재 확인 두 줄은 이 안내를 위해 덧붙인 것이며 따로 실행하지 않았습니다. 같은 ZIP을 Windows 10(빌드 19045) 한 PC의 파일 탐색기 안에서 열어, 압축 폴더 도구 리본의 [압축 풀기]와 Windows 압축 폴더 마법사로 한글·공백·괄호가 든 새 폴더에 풀었을 때도 `app\electron.exe` 구조와 파일 4,635개의 경로·크기·SHA-256, `app` 아래 폴더 168개가 원본과 일치했고 ZIP 자체도 풀기 전후 같았습니다. 이 탐색기로 푼 폴더도 §3 블록으로 실제 실행해 환영 화면과 합성 원고 열기를 확인했습니다(아래 "이 예시를 어떻게 확인했는지"). **확인하지 못한 것:** 그 ZIP의 항목 이름 구분자가 백슬래시라서, 위에서 확인한 두 경로(5.1 `Expand-Archive`와 이 PC의 내장 탐색기 리본) 밖의 경우, 즉 다른 Windows 버전·다른 OS, `.zip`에 연결된 다른 압축 프로그램으로 푸는 경우의 호환성은 확인하지 않았고 보장하지 않습니다. 인터넷에서 내려받은 ZIP, SmartScreen 경고, 다른 PC, 서명, 설치는 확인하지 않았습니다. 이 ZIP 확인은 기본 빌드(`electron.exe`)의 것이며, 선택형 `LoreWeave.exe` 폴더를 ZIP으로 만들어 푼 적은 없습니다. 파일 접근 관측의 범위와 한계는 아래에 따로 적었습니다.

## 2. 시작 전 지킬 것

- **실제 작품 폴더를 열지 마세요.** 이 안내의 시험은 새로 만든 합성 원고로만 합니다.
- **항상 `--user-data-dir=<새 빈 폴더>`로 실행하세요.** 이 인자 없이(예: exe를 더블클릭하거나 바로가기로) 실행하면 앱의 설정·키가 Electron 기본 위치로 잡혀 이미 있는 설정이나 키에 닿을 수 있습니다. 기본 위치에 실제로 무엇이 있는지는 이 안내를 만들며 열어 보지 않았습니다.
- 실제 원고로 쓰려면 먼저 **직접 복사해 백업**하세요. LoreWeave에는 자동 백업 기능이 없습니다.
- **같은 `.md` 파일은 한 번에 한 프로그램에서만 수정하세요.** LoreWeave와 메모장 같은 다른 편집기에서 같은 화를 동시에 열어 고치지 마세요. 다른 편집기에 열어 둔 **오래된 내용을 그 편집기에서 저장하면** 이미 저장된 LoreWeave의 내용을 덮어쓸 수 있고, LoreWeave는 그 일이 일어난 뒤에야 알 수 있습니다. LoreWeave에 **아직 저장하지 않은 편집**이 남아 있을 때의 보호는 이번에 확인한 한 가지 조건, 즉 미저장 편집을 그대로 둔 채 LoreWeave 창이 포커스를 유지한 상태에서 메모장이 저장한 경우에만 확인했습니다(충돌 안내와 화면 글 유지). 두 경우를 구분해서 알아 두고, 충돌 안내가 떴을 때의 두 선택은 확인 창을 수락하면 이렇게 됩니다. **[내 것으로 덮어쓰기]: 화면의 내용이 파일에도 저장되고, 외부 편집기가 저장한 내용은 파일에서 사라집니다. [디스크 내용 불러오기 (내 수정은 버림)]: 외부 편집기가 저장한 내용이 화면과 파일에 남고, 화면의 저장하지 않은 수정은 사라집니다.** 확인한 조건과 한계는 아래 [검증 현황](#검증-현황)의 메모장 행을 보세요.
- AI 기능(OpenAI API 키 입력, 분석·검사)은 이 흐름에 필요하지 않으니 시험 중 키를 넣지 마세요.

## 3. 새 격리 폴더로 시작하기 (PowerShell 예시)

`$app`에는 전달받은 폴더 경로(ZIP이면 [§1](#zip으로-받았다면-먼저-전체를-풀어-주세요)에서 푼, 실행 파일이 든 폴더)를, `$root`에는 **아직 없는 새 경로**를 넣습니다(상위 폴더는 미리 있어야 합니다). 이미 있는 경로면 아무것도 쓰기 전에 중단합니다.

**치환 방법:** 아래 코드 블록에서 `<전달받은 폴더 경로>`와 `<새 시험 폴더 경로>` 두 자리표시자만 실제 경로로 바꾸세요(나머지는 그대로). 경로는 작은따옴표 문자열 안에 적습니다. 경로에 작은따옴표(`'`)가 있으면 PowerShell 규칙대로 `''`로 두 번 씁니다(이 입력 방식은 안내일 뿐 검증하지 않았습니다). 자리표시자를 그대로 두면 실행 파일을 찾지 못해 중단합니다.

**이 예시를 어떻게 확인했는지** (아래 범위로만):

- **대역 실행 파일로 두 셸의 인자 전달을 확인:** Windows PowerShell 5.1과 pwsh 7에서, 한글·공백·괄호가 든 경로로 이 블록을 실행했습니다. 실행 파일 자리에 받은 인자를 파일로 남기는 대역 exe를 두었고, 받은 인자는 `--user-data-dir=<새 root>\userdata` 하나였습니다. 이미 있는 root는 쓰기 전에 중단했고(기존 파일 불변, 실행 없음), 실행 파일이 없는 경우와 자리표시자를 바꾸지 않은 경우도 중단했습니다.
- **Windows PowerShell 5.1에서의 첫 실제 앱 관측(제품 시작 직전 관측 기록 시각: 한국 시각 2026-11-23 00:10):** 기본 폴더 실행본(제품 소스 726a456, 이후 main의 변경은 문서뿐)을 이 블록으로 실행했습니다. 블록과 실행한 스크립트의 차이는 두 자리표시자 줄뿐이었고, 경로에는 한글·공백·괄호가 있었습니다. **다만 제품 시작 직전 상태를 보려고 `NODE_OPTIONS` 환경 변수로 읽기 전용 사전 관측기를 추가했으므로, 문서 예시 그대로의 환경은 아닙니다.** 관측 결과: 앱 인자는 실행 파일과 `--user-data-dir=<새 root>\userdata` 하나뿐이었고, 제품 main 직전에 userData·sessionData가 그 폴더와 같고 비어 있으며 아직 ready 상태가 아니었습니다. 환영 화면에서 실제 Windows 폴더 선택으로 `novel`을 열어 두 화와 각 한글 본문을 확인했고, `settings.json`의 마지막 프로젝트는 합성 경로, `.loreweave\index.db`는 합성 원고 폴더 아래였습니다. 5.1에서 `Set-Content -Encoding utf8`로 만든 원고 두 개에는 UTF-8 BOM이 붙었습니다(pwsh는 대역 검사에서 BOM이 없었음).
- **탐색기로 푼 폴더를 pwsh 7에서 실제 실행(Windows 10 빌드 19045, pwsh 7.7.0-rc.1, 제품 소스 726a456, 이후 main까지 제품 입력 변경 없음):** §3 블록(경로 두 곳만 치환)으로 실행했고, 앞의 5.1 실행과 같이 환경 변수로 읽기 전용 관측용 프리로드를 추가했습니다(문서 예시 그대로의 환경이 아님). 제품 main 직전에 userData·sessionData가 같은 빈 시험 폴더였고 아직 ready 상태가 아니었습니다. 환영 화면, 합성 두 화의 본문, 환경설정 열기, 정상 종료를 직접 확인했습니다. 폴더 선택 창은 시험 폴더가 아니라 OS의 다운로드 위치에서 열렸고, 합성 원고 폴더만 골랐습니다(실제 작품 폴더를 고르지 마세요).
- **그때의 파일 접근 기록(시험 프로세스의 main 프로세스가 쓰는 Node 파일·`node:sqlite`·자식 프로세스 API를 경로만 기록):** 기록 820건 중 사용자 프로필로 볼 후보 경로는 0건이었습니다. 허용한 시험 폴더·실행본 폴더 밖의 5건은 관측용 프리로드 파일 2건, 증거 파일 2건, Electron이 시작할 때 실행본 폴더의 상위에서 `update.exe` 존재를 확인한 1건이었습니다. `settings.json`과 키 파일 조회는 시험 userData 안이었고(키 파일은 없었음), `index.db` 열기는 합성 원고의 `.loreweave` 안이었으며 AI는 실행하지 않았습니다. 기록 도구의 검출·필터는 별도 합성 경로의 읽기·쓰기 대조 14개로 확인했습니다. **관측하지 못한 것:** Chromium 네이티브 파일 접근, 다른 프로세스, Node 내부 모듈 로더, 후킹하지 않은 API·경로의 접근. 그러므로 "네이티브 접근이 없었다"거나 "완전히 격리된다"는 뜻이 아닙니다.
- **확인하지 못한 것:** 선택형 `LoreWeave.exe`로 이 블록을 그대로 실행한 경우(선택형은 검사용 실행으로 한 번만 확인했습니다. 검증 현황 표 참고), 관측용 프리로드 없이 실행한 경우, 다른 PC, 내려받은 ZIP과 SmartScreen. 5.1 쪽 실제 앱 관측에서는 기본 프로필 경로의 파일 접근을 추적하지 않았고(그 경로를 열어 보지도 않았습니다), 확인된 것은 제품 main 직전의 userData·sessionData와 실행 뒤 시험 위치에 생긴 설정·색인까지입니다.

```powershell
$ErrorActionPreference = 'Stop'
$app  = '<전달받은 폴더 경로>'     # 예: 압축을 푼 폴더. electron.exe(또는 LoreWeave.exe)가 든 폴더
$exe  = 'electron.exe'            # 브랜드 빌드면 'LoreWeave.exe'
$root = '<새 시험 폴더 경로>'      # 실제 작품·실제 프로필과 무관한 새 경로
if (-not (Test-Path -LiteralPath "$app\$exe")) { throw "실행 파일이 없습니다: $app\$exe" }
if (Test-Path -LiteralPath $root) { throw "이미 있는 경로입니다. 다른 새 경로를 쓰세요: $root" }

# 새 userData와 합성 원고 폴더 (원고는 novel\chapters\001.md, 002.md … 형식)
New-Item -ItemType Directory -Path $root | Out-Null
New-Item -ItemType Directory -Path "$root\userdata", "$root\novel\chapters" | Out-Null
Set-Content -LiteralPath "$root\novel\chapters\001.md" -Value '첫 줄입니다.' -Encoding utf8
Set-Content -LiteralPath "$root\novel\chapters\002.md" -Value '이웃 본문입니다.' -Encoding utf8

& "$app\$exe" --user-data-dir="$root\userdata"
```

## 4. AI 없이 따라가는 짧은 흐름

1. 환영 화면에서 **[원고 폴더 열기]** → 위에서 만든 `novel` 폴더를 고릅니다. `chapters\001.md`, `002.md`가 화로 보입니다.
2. 첫째 화를 열어 한글을 입력합니다. 잠시 뒤 자동 저장되고 Ctrl+S로 바로 저장할 수도 있습니다. 상태줄이 "저장됨"으로 바뀌는지 봅니다.
3. 검색창에 `이웃`을 입력하고 Enter → 결과를 눌러 그 화로 이동하고, **[목록으로]**로 화 목록에 돌아옵니다.
4. 창을 닫고, 같은 `--user-data-dir`로 다시 실행합니다. 마지막으로 연 폴더가 다시 열리고 입력한 본문이 남아 있어야 합니다.
5. (선택) `001.md`를 메모장이나 VS Code로 열어 입력한 글이 파일에 들어갔는지 봅니다. 앱이 열린 동안 같은 파일을 다른 프로그램에서 바꾸면 충돌 안내가 나올 수 있고, 안내가 나온 동안 앱은 디스크의 변경본을 덮어쓰지 않습니다. 이 동작은 자동 검사와 한 번의 실제 창 관측으로만 확인했고 범위가 제한적입니다(아래 표).

## 6. 문제를 알릴 때

이 안내는 **어디로 보내는지는 정하지 않습니다.** 폴더나 ZIP을 전달해 준 쪽이 알려 준 방법으로 보내고, 알려 준 방법이 없으면 보내기 전에 그쪽에 먼저 물어보세요(이 저장소의 공개 이슈 등은 이 베타의 제보 경로로 확인되지 않았습니다). 어떤 방법이든 **공개된 곳이라면 아래 "넣지 말 것"을 꼭 지키세요.** 확인하지 못한 항목은 비우지 말고 "확인하지 못함"이라고 적어 주세요.

**넣을 것** (짧은 번호 목록으로)

1. **받은 빌드:** 폴더 또는 ZIP의 이름과 받은 날짜, 실행 파일 이름(`electron.exe` 또는 `LoreWeave.exe`), 폴더 안 `version` 파일의 Electron 버전과 `resources\app\package.json`의 `version`. ZIP이라면 SHA-256(`Get-FileHash -LiteralPath '<ZIP 파일 경로>' -Algorithm SHA256`, 경로 자체는 적지 마세요). 앱 화면에는 버전 표시가 없고 위 값만으로는 정확한 소스 커밋을 알 수 없으니, 전달한 쪽이 알려 준 빌드 식별자가 있으면 함께 적어 주세요.
2. **Windows:** `cmd /c ver`의 결과(예: `Microsoft Windows [Version 10.0.…]`)와, 해당한다면 한글 입력기 등 사용한 입력 방식.
3. **최소 재현 단계:** [§3](#3-새-격리-폴더로-시작하기-powershell-예시)처럼 새 격리 프로필과 합성 원고에서 다시 만들 수 있는 가장 짧은 단계. 단계마다 한 일을 적어 주세요(예: "첫째 화 끝에 글자 입력 → Ctrl+S"). 항상 나는지, 가끔 나는지, 한 번만 났는지도 적어 주세요.
4. **기대한 결과와 실제 결과**를 한 줄씩.
5. **원고 영향:** 합성 파일의 글자가 사라졌는지, 파일이 생기거나 없어졌거나 이름이 바뀌었는지. 확인했다면 전후의 파일 크기나 SHA-256을 함께 적고, 확인하지 못했으면 그렇게 적어 주세요.

**넣지 말 것**

- **실제 원고**의 내용과 실제 원고 폴더의 이름·경로
- OpenAI API 키와 `openai-key.bin`, `settings.json`, 원고 폴더 안 `.loreweave`의 `index.db`·`ai.db` 같은 데이터베이스 파일
- 사용자 이름이 들어 있는 경로(`C:\Users\<이름>\…`은 `C:\Users\<사용자>\…`처럼 바꾸세요)
- 원고 내용이 보이는 스크린샷·화면 녹화. 필요하면 합성 원고로 다시 재현한 화면만 쓰세요.
- 실제 작품에서 문제가 생겼다면(이 안내는 실제 원고를 열지 않도록 했습니다) 그 파일을 올리지 말고 "실제 원고에서 발생"과 증상만 설명한 뒤 전달한 쪽과 따로 상의하세요.
