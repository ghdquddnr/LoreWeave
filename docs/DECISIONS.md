## 2026-10-24 · Chapter ID

- **UUID v4** (`crypto.randomUUID()`), frontmatter `id` 필드에 저장.
- 이유: 의존성 없음, 표준. 챕터 순서는 ID가 아니라 별도 필드로 표현하므로 ULID의 정렬성은 불필요.
- 주의 (M1): 파일 복사로 인한 중복 ID를 로드 시 감지해 재발급하는 규칙이 필요하다.

## 2026-10-24 · M0-A 실행 조건

- 평가 모델: `gpt-6.1-sol`, `gpt-6-luna` 두 개로 제한 (API 키 권한도 이 두 모델로 제한됨). "GPT-6 미정" 항목을 대체한다.
- 가격 (Standard, 1M 토큰, ≤272K 입력, 2026-10-24 공식 가격표 확인): sol 입력 $2.00 / 캐시 입력 $0.10 / 출력 $10.00, luna 입력 $0.10 / 캐시 입력 $0.01 / 출력 $0.50.
- 비용 상한: **$10** (선불 충전 + OpenAI 측 사용 한도). 호출 래퍼도 누적 비용을 기록하고 상한 전에 중단한다.
- 챕터 분량: 화당 약 1,050~1,350자를 그대로 유지한다 (계획 1,200~2,000자). 분량 영향은 scale probe로 본다.
- Ground truth 확정: blind cold-read 검수 결과 정답 30/30 일치, 라벨 밖 오류 0, 함정 오탐 0.

- 유지 자산(benchmark v2, 평가기와 테스트, Finding 스키마, 보고서, 요약 결과)은 main의 `spikes/m0a-ai-feasibility/`에 둔다. 전략 구현, 러너, 호출 래퍼, 실행별 결과는 태그에만 남긴다.

## 2026-10-24 · M0-B 결과

- M0-B 성공 기준 충족. 보고서: `docs/spikes/M0B-REPORT.md`.
- 에디터는 TipTap을 유지한다. 원고 형식은 C3(한 줄 = 한 문단, 빈 줄 = 빈 문단)이고, Markdown 변환기는 직접 작성한다: [ADR 0002](decisions/0002-editor-and-manuscript-format.md)
- TipTap 공식 Markdown 확장과 `tiptap-markdown`은 쓰지 않는다. 웹소설 표기 `[대사]`를 이스케이프하고, 공식 확장은 스키마 밖 문법의 글자를 지운다.
- VS Code 미리보기에서 C3 원고의 줄이 한 문단으로 합쳐 보이는 것은 받아들인다 (Obsidian은 정상).
- 붙여넣기는 서식을 지우고 글자만 넣는다.
- 유지 자산(코퍼스, round-trip 하네스와 테스트, 결과, 체크리스트, 보고서)은 main의 `spikes/m0b-editor-feasibility/`에 둔다. 변환기, 검증 패널, 성능 러너, Electron 창은 태그 `spike-m0b-2026-10-24`에만 남긴다.

## 2026-10-24 · M1 저장 전 검사와 `*` 입력

- 작가가 입력한 `*`가 다시 열 때 강조로 읽히는 경우: **친 글자 그대로 저장하고 경고**한다 (사용자 결정). 파일에서 글자가 사라지지 않으므로 원고는 안전하다.
- 저장 전 검사(ADR 0002 결정 5)는 둘로 나눈다. 에디터의 글자가 파일에 다 들어가지 않으면 **저장하지 않는다**. 다시 열면 모양만 달라지는 경우(강조, 인용 안 제목 등)는 **저장하고 위치를 알린다**.
- Shift+Enter는 새 문단(Enter와 같음), 인용 안에는 문단만 둔다. 붙여넣기는 글자만, 바깥에서 끌어다 놓기는 받지 않는다.

## 2026-10-24 · M2 범위와 SQLite 변경

- 계획: `docs/M2-PLAN.md`
- **변경됨**: Database `better-sqlite3 + Raw SQL` → **`node:sqlite`(Electron 내장) + Raw SQL**. 네이티브 빌드(electron-rebuild)가 필요 없고 Electron 44(Node 24.22)에서 FTS5까지 동작한다. 접근은 한 모듈에 모은다. 색인은 다시 만들 수 있어서 막히면 되돌릴 수 있다.
- 검색: 원고 전체 검색과 결과로 이동. 바꾸기는 제외.
- 중복 id: 경고와 "새 id 발급" 버튼. 앱이 자동으로 파일을 고치지 않는다 (2026-10-24 Chapter ID의 "M1 재발급 규칙" 메모를 대체).
- id 없는 기존 화: 건드리지 않는다. 색인은 파일 이름으로 화를 구분한다.

## 2026-10-25 · M2 결과

- M2 성공 기준 충족. 보고서: `docs/M2-REPORT.md`.
- 검색은 부분 문자열 훑기(`instr`)로 확정한다. 1000화 검색 p95가 146ms라 FTS5는 넣지 않았다. 측정이 기준을 넘으면 다시 본다.

## 2026-10-25 · M4 범위

- 계획: `docs/M4-PLAN.md`
- 실행: [이 화 검사] 버튼. 현재 화를 앞 화들과 비교한다. 분석이 필요한 화는 먼저 분석하고 그 비용까지 합쳐 확인받는다. [전체 검사]는 두지 않는다.
- 탐지는 ADR 0001의 B 전략과 M0-A 탐지 프롬프트를 그대로 쓴다. 이 화의 문장과 근거 문장이 원고에 없는 결과는 저장하지 않는다.
- 결과 처리: 보기와 [무시]. 어느 쪽이 맞는지는 작가가 원고를 고쳐서 정한다. "앞 화 쪽이 틀렸다" 표시(echo 차단)는 v0.1 이후에 검토한다.
- 모델: 추출과 같은 설정 모델 하나 (기본 `gpt-6-luna`).
- 표시: 오른쪽 패널 목록. 본문 밑줄은 하지 않는다.
