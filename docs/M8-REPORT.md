# M8 결과: 긴 화를 나눠 추출

- 날짜: 2026-10-25
- 계획: [`M8-PLAN.md`](M8-PLAN.md)
- PR: #51 (나눠 추출), 이 PR (측정·보고서)
- 집계: [`spikes/m8-real/results.json`](../spikes/m8-real/results.json). 원문, 심은 목록, 판정표는 저장소 밖에 있다. 작품 이름과 인물 이름은 적지 않는다.

## 결론

**나눠 추출로 사실이 2.2배 늘었고, 실제 원고에 심은 오류를 M7보다 많이 찾았다.**

- 찾은 비율: 30~35% → 45%
- 근거 retrieval 기준(15/20)과 Recall 기준(50%)에는 못 미쳤다.
- 화당 오탐은 늘었지만 기준 안이다.
- 검사 비용은 사실 수만큼 약 2배가 됐다.

| 기준 (M8-PLAN 4절) | M7 | M8 | 판정 |
|---|---|---|---|
| 근거 retrieval ≥ 15/20 | 10/20 | **12/20** | 미달 |
| Recall (사람 판정, 기준값 적용 뒤) ≥ 50% | 30% (6/20) | **45% (9/20)** | 미달 |
| 화당 오탐 ≤ 1 (사람 판정) | 0.05 | 0.45 (판단 어려움 포함 0.60) | 충족 |
| 추출 인용 보존 ≥ 90% | 91.9% | 92.8% | 충족 |
| 비용 ≤ $1.5 (Costs API) | | Costs API: 실행 전 $5.6888 → 23:07 KST $6.8615, **+$1.1727** (22:59 실행 직후에는 +$0.645로 반영 중이었음). 토큰 계산 $1.173과 일치 | 충족 |
| 합성 원고 영향 | | M0-A 화는 모두 1,500자보다 짧아 한 조각이다 (테스트). 입력·프롬프트·호출 수는 M7과 같다. 저장 결과는 같은 사실 중복 제거·요약 공백 정리 때문에 달라질 수 있고, 탐지율이 같은지는 재지 않았다 | 부분 확인 |

확신도 기준값(0.7)을 적용하기 전과 후의 Recall이 같다 (찾은 9개 모두 확신 0.84 이상).

## 측정

- **원고**: M7과 같은 복사본(심은 오류 20개)을 새로 복사해, 265화 전부를 나눠 추출로 다시 분석했다.
- **검사**: 같은 20화를 제품 설정으로 검사했다 (400개씩 나눠 검사, 확신도 0.7 미만 숨김).
- **분석**
  - 265화, 2,517초, 토큰 계산 $0.703 (M6 $0.340의 약 2배)
  - 사실 8,588개 (M7 3,887개의 2.2배), 화당 32.4개
  - 인용 보존 92.8%
- **검사**
  - 앞 화 사실: 25~4,513개 (1~12번 나눔)
  - 검사 한 번: $0.0007~$0.0427, 1.4~47초
  - 20화 합계: 토큰 계산 $0.470
- **비용**
  - 토큰 계산: 분석 $0.703 + 검사 $0.470 = $1.173
  - Costs API: 실행 전 $5.6888, 실행 직후(22:59 KST) $6.3335 (+$0.645, 반영 중), 23:07 KST $6.8615 (**+$1.1727**)
  - 반영이 끝난 값은 토큰 계산과 일치한다. 실행 직후 값은 반영이 늦어 작게 나온다. Costs API 값은 실시간 지출 상한을 보장하지 않는다.
  - 누적 실비 $6.8615, 한도 $10 중 약 $3.14 남음

### 심은 오류 20개

| | M7 | M8 |
|---|---|---|
| 근거 retrieval | 10 | 12 |
| 찾음 (사람 판정) | 7 (기준값 적용 뒤 6) | 9 |
| 근거를 받았을 때 찾은 비율 (judge) | 3/10 | 5/12 |

- 새로 근거가 들어간 것은 5개다 (서클 단계, 인물의 성별, 시간 배속, 첫 만남, 마법 서클 하나). 처음 보고에서 서클 단계(S03)를 빠뜨렸다 (감독 검토로 고침).
- 반대로 M7에서는 들어갔던 3개가 빠졌다 (성적 등수, 직업, 시합 상대 이름). 다시 추출하면 같은 화에서도 뽑히는 사실이 조금씩 다르다. 모델 출력이 매번 달라서 생기는 일이고, 이번 표본(20개)에서는 오류 2~3개 차이가 우연일 수 있다.
- 찾은 것: 서클 단계 2개, 직업, 호칭, 정령 수, 나이, 최대 접속 시간, 마법 서클, 가면 모양
- 놓친 것: 성적 등수, 장소, 학년, 코드네임, 인물의 성별, 시간 배속 계산, 시합 상대 이름, 첫 만남, 직책, 아이템 능력치, 마법 서클 하나

검사 결과는 모두 24개다: 심은 오류를 찾은 것 9개 + 같은 심은 오류를 한 번 더 짚은 중복 2개(정령 수, 나이) + 정답표 밖 13개. 중복 2개는 오탐으로 세지 않는다.

### 정답표 밖의 결과 13개 (사람 판정)

| 판정 | 수 | 내용 |
|---|---|---|
| 정당한 변화 | 5 | 실력을 숨긴다고 같은 화에서 밝힘 (2), 시간이 지나 능력치가 늘어남, 작중 다른 이름(별명)으로 부름, 작중에서 설명되는 가상현실 재회 |
| 잘못 읽음 | 4 | 다른 뜻의 "정체성" 서술을 엮음, 농담 섞인 외모 묘사로 성별을 판단, 마법을 창의적으로 쓴 장면을 설정 위반으로 봄, 미리 저장한 마법 사용을 설정 위반으로 봄 |
| 판단 어려움 | 3 | 서로 다른 인물의 같은 이름 아이템 등급, 인물의 팔, 결말부의 사망 인물 등장 |
| 맞는 지적 | 1 | 원고의 사소한 계산 차이 (현실 20시간 × 4배 = 80시간인데 "3일 반"이라고 씀) |

- 사실이 늘면서 오탐도 늘었다 (M7 20화에 1개 → M8 9개, 판단 어려움 3개 별도).
- 판단 어려움을 뺀 오탐의 확신도는 0.78~0.99라 확신도로는 거르지 못한다.
- 원고에 원래 있던 사소한 모순 하나를 처음으로 찾았다.

## 알게 된 것

1. **나눠 추출은 효과가 있다.** 사실이 2.2배가 되고, 근거가 들어간 오류와 찾은 오류가 늘었다.
2. **그래도 짧은 표기는 잘 안 뽑힌다.** "수영장(4서클)", 상태창의 "- 모든 스텟 +300", 일과표 한 줄처럼 문장이 아닌 줄은 나눠도 사실로 잘 잡히지 않는다.
3. **추출은 매번 조금씩 다르다.** 같은 화를 다시 추출하면 뽑히는 사실이 달라져, 한 번 잡혔던 근거가 빠지기도 한다. 한 번의 측정으로 작은 차이를 판단하면 안 된다.
4. **비용·시간이 사실 수에 비례해 는다.**
   - 분석 비용 약 2배, 검사 비용 약 2배
   - 265화 위치의 검사는 12번에 나눠 $0.043, 41초가 걸렸다 (M5 기준 30초를 넘는다).
   - 장편 전체를 분석하고 자주 검사하면 체감될 비용이다.
5. **오탐이 늘었다.** 비교할 사실이 많아지며 "정당한 변화"와 "잘못 읽음"이 함께 늘었다. 아직 화당 1개 미만이지만 방향은 나쁘다.

## 한계

- 심은 오류 20개, 작품 하나, 모델 하나(luna), 1회다. M7과 M8의 차이(오류 2~3개)도 일부는 추출이 매번 달라지는 데서 온다.
- 비용은 23:07 KST에 Costs API로 다시 확인한 값(+$1.1727)이 토큰 계산과 일치했다. 다만 Costs API는 일반적으로 반영이 늦고(실행 직후 값은 작게 나온다) 하루 단위로 조직 전체를 집계하므로, 같은 시간대의 다른 호출이 섞일 수 있고 실시간 지출 상한을 보장하지 않는다.

## 다음 단계 후보

1. **상태창·목록 줄 따로 다루기**: 문장이 아닌 짧은 줄(상태창, 마법 목록, 일과표)을 사실로 뽑도록 추출 프롬프트를 고친다. 프롬프트가 바뀌므로 M0-A 기준으로 다시 잰다.
2. **검사 시간 줄이기**: 나눈 묶음을 동시에 더 많이 보낸다 (지금 2개). 비용은 같고 시간이 준다.
3. **같은 사실 정리**: 화마다 다시 말하는 같은 설정(이름, 서클, 직업)을 하나로 묶어 넘기는 사실 수를 줄인다. 비용과 오탐을 함께 줄일 수 있다.
4. **반복 측정**: 같은 조건으로 2~3회 측정해 우연한 차이를 가린다.
