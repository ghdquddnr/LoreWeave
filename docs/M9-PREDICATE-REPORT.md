## 결론

**사실 더하기 실험도 기준 8(M4 회귀)을 충족하지 못했다.**

- m4-3이 test Recall 16/20으로, 회별 기준 17/20에 미달했다.
- runner가 설계대로 실제 원고 회차를 시작하지 않았다 (실제 원고 호출 0).
- 기준은 완화하지 않는다.
- 제품 사실 고르기와 detect-1은 그대로다.

| 회 | test Recall | Precision | 화당 오탐 (÷14) | 기준 8 |
|---|---|---|---|---|
| m4-1 | 17/20 | 100% | 0 | 통과 |
| m4-2 | 17/20 | 100% | 0 | 통과 |
| m4-3 | **16/20** | 88.9% | 0.143 (2개) | **미달** |

- 수치는 자동 채점(확신도 0.7 적용 뒤)이다. 숨긴 결과가 세 회 모두 0개라 필터 전후 값이 같다.
- 맞는 결과의 최저 확신도는 0.84다.
- 함정 오탐은 세 회 모두 0이다.

**가설이 겨냥한 E23을 이번에 처음 찾았다 (관찰).**

- 세 회 모두 추가 입력에 7화의 같은 내용 사실("투자금 3억 원")이 들어갔다. 기준 입력에는 이 사실이 없다.
  - 이 판정은 저장된 분석으로 요청을 다시 만들어 본 것이다 (아래 "증거의 한계").
- m4-2·m4-3은 그 사실의 원문을 근거로 E23을 찾았다. m4-1은 같은 입력에서 놓쳤다.
- 이전에는 네 회(detect-1 1회, detect-2 후보 3회) 모두 놓쳤다. 그때는 이 사실이 입력에 없었다.
- **이것은 관찰이다.** "사실을 더한 것이 E23 발견의 원인"이라는 인과 효과는 확인하지 않았다.
  - 비교 대상은 다른 시점의 실행이고 회 수도 적다(이번 3회 중 2회, 이전 4회 중 0회).
  - 같은 입력에서도 회마다 결과가 갈린다.
- Recall은 기준을 넘지 못했다. 다른 오류는 같은 입력에서도 회마다 찾거나 놓쳤다.

## 실행

- **고정값**: gpt-6-luna, 판단 프롬프트 detect-1(복사본에 남는 검사 버전만 `detect-1+predicate-match`), 묶음 동시 2, 출력 상한 16,000토큰(추론 포함), 요청마다 재시도 최대 1회, SDK 재시도 0.
- **호출 전 대조** (다섯 회차 모두): M4 3회는 각 기준 14/14·추가 14/14, 실제 원고 2회는 각 기준 20/20·추가 20/20.
  - M4는 당시 평가기 출력이 없어 화·인용 순서 대조를 건너뛰었다.
- **보낸 요청**: M4 14화 × 3회 = 42회. 재시도는 0회 일어났다. 실제 원고는 0회다.
- **회차 상태**: m4-1·m4-2·m4-3은 완주했다. real-1·real-2는 시작하지 않았다.

**정답표 밖 2개 (m4-3, 8화)의 사람 판정: E13의 중복**

- 평가기는 2개를 오탐(unlabeled)으로 셌다.
- 두 결과는 정답표 오류 E13(2007년에 사망한 교수가 2008년 3월인 8화에 연구실에서 민수와 대화함)을 같은 장면의 다른 문장으로 짚은 것이다.
- 평가기는 정답표가 지정한 문장 위치만 맞추므로 정답표 밖으로 분류했다.
- E13은 같은 회에서 이미 찾았다. 그래서 사람 판정으로는 중복이고, 오탐이 아니다.
- **사람 판정 참고값**: 중복 2개를 오탐에서 **제거**한 값이다. TP로 다시 세지 않았다. 평가기의 중복 처리와 같다 (중복은 TP도 오탐도 아니다).
  - Precision = test TP / (test TP + 오탐) = 16 / (16 + 0) = 100%, 화당 오탐 0/14.
  - 자동 채점 값은 test TP 16, 오탐 2, Precision 16 / (16 + 2) = 88.9%, 화당 오탐 2/14 = 0.143이다. 이 값을 그대로 보존한다.
  - **관문(기준 8)은 자동 채점으로 고정했으므로 판정은 바뀌지 않는다.** 어느 쪽으로 봐도 Recall 16/20은 미달이다.
- 이 판정은 저장된 결과(대상 문장, 근거 문장)와 원고 본문을 직접 대조한 것이다. 모델 출력을 관측한 기록에 근거한다.

**새로 놓친 오류**

- 이전 detect-1 1회에서 찾던 오류 중 이번에 놓친 것:
  - E29(15화 왼손잡이): m4-1·m4-2에서 놓쳤다.
  - E06(10화 나이): m4-3에서 놓쳤다.
  - E20: m4-2·m4-3에서 놓쳤다. E30: m4-3에서 놓쳤다.
- E29의 15화와 E06의 10화에 더한 사실은 각각 2개, 1개뿐이고, 같은 입력에서도 회마다 결과가 갈렸다.
- 그래서 더한 사실 때문인지는 **확인하지 않았다** (원인 미확인).

## 평가기 출력과 증거의 한계 (이번에 확인)

- 회차별 `predictions.json`의 사실 목록(context)은 `export-predictions`가 저장된 분석에 **제품의 이름 기준 고르기**를 다시 적용해 만든 것이다. 그래서 이 실험에서 실제로 더해 보낸 사실이 빠져 있다.
- 따라서 평가기의 retrieval(86.7%)은 기준 입력의 값이다. 추가 입력의 retrieval은 오프라인 계산(`M9-FOLLOWUP.md`, 27/30)을 쓴다.
- E23의 입력 판정은 저장된 분석으로 runner와 같은 함수(`buildPredicateCheck`)를 다시 돌려 요청을 **재구성**한 것이다. 보낸 요청 바이트를 직접 관측한 것이 아니다 (요청 자체는 저장하지 않는다).
  - 같다고 보는 근거: 실행 전 대조와 첫 호출 직전·화별 전송 직전 재확인에서, 추가 요청 fingerprint가 같은 저장 분석에서 나온 것과 일치했다. 실행 뒤 복사본 분석은 바뀌지 않았다.
  - 이것은 정황이며 직접 관측은 아니다.
- 결과(findings)와 회별 자동 채점은 영향을 받지 않는다.

## 비용

- **단계 장부** (`m9p-predicate`, 승인 ID 묶음, 한도 $1.20)
  - 시도 42회, 모두 정산됐다. 불명 0, 미정산 0, 잠금 없음.
  - 누적 **$0.022208**이다. 회별로는 m4-1 $0.0140(캐시 쓰기), m4-2 $0.0045, m4-3 $0.0038이다.
  - 남은 단계 한도는 $1.177792다. 이번 승인은 M4 미달로 끝났으므로 이월하지 않는다.
- **Costs API** (실비, 이번 보고서 수정에서는 다시 조회하지 않았다)
  - 조회 구간은 두 번 모두 2026-10-01부터 조회 시점까지다 (UTC 날짜 합계). 제 기록은 CLI가 소수 넷째 자리까지 보여 준 값이다.
  - 실행 전: 2026-10-26 02:12 KST **$6.8844**. 감독 기록의 같은 시점 근처 정밀값은 $6.88441423이다.
  - 실행 뒤: 02:20 KST **$6.8967**. 반올림 전 값은 기록하지 않았다.
  - 차이 +$0.0123은 반올림 값끼리의 차다(±$0.0001).
  - **귀속 가정**: 이 차이를 전부 이번 실행으로 본다. 같은 조직의 다른 지출(다른 키, 다른 작업)이 그 사이에 있었는지는 Costs API로 구분할 수 없다. 이전 실행 지출의 늦은 반영이 섞였을 수도 있다.
  - **보수적 잔여 계산**:
    - 남은 금액 = $10 − 실행 뒤 Costs − max(0, 장부 지출 − 반영분)
    - = $10 − $6.8967 − ($0.022208 − $0.0123) = 약 **$3.0934**
    - 반영분을 이번 실행에 귀속했으므로, 장부 지출 중 아직 반영되지 않은 몫을 더 뺀다. 다른 지출이 섞였다면 실제 잔여는 이보다 적을 수 있다.
- 복사본 ai.db의 `calls`에 있는 과거 호출은 이번 비용에 섞지 않았다.
