# M9 계획: 판단 프롬프트의 "변화 판단" 고치기

- 날짜: 2026-10-26
- 근거: [`M9-DIAGNOSIS.md`](M9-DIAGNOSIS.md), `spikes/m9-diagnosis/results.json`
- 이전 단계: [`M8-REPORT.md`](M8-REPORT.md). Recall 45%, retrieval 12/20으로 목표에 못 미쳤다.

## 1. 왜 이것인가

진단 결과, 실패는 판단 단계 19개, 추출 단계 4개다.

- **판단 단계 19개**: 근거가 있었는데 놓친 7개, 오탐과 판단 어려움 12개.
- 판단 실패 중 9개는 같은 문제다. **값이 달라진 것이 정당한 변화인지 모순인지를 잘못 정했다.**
  - 놓친 4개(S04, S14, S19, S05): 설명 없는 변화를 보고하지 않았다.
  - 오탐 5개(U01, U03, U05, U06, U12): 설명이 있는 변화를 보고했다. 이 중 3개는 설명이 검사한 화 안에 있었다.

세 후보를 비교했다 (개선 가능 수는 진단에서 센 상한이다).

| 후보 | 놓친 것 중 개선 가능 | 오탐 중 개선 가능 | 위험 |
|---|---|---|---|
| **판단 프롬프트의 변화 판단 절차** | 3~5 (S04, S14, S19; 계산 S08; S05 일부) | 3~4 (U05, U06, U12; U01 일부) | M0-A에서 검증한 문구를 바꾼다 |
| 정보 손실 없는 입력 구성 (같은 속성 사실을 짝지어 앞에 보이기) | 최대 3 (S04, S14, S19) | 0. U01·U05·U06은 짝지으면 더 눈에 띌 수 있다 | 대상 화의 추출에 기대야 한다 (S05·S07은 대상 줄이 추출되지 않았다) |
| 짧은 표기 추출 | 2~3 (S01, S16, S10 일부) | 0. 사실이 늘어 M8처럼 오탐이 늘 수 있다 | 265화 재추출 비용 |

**판단 프롬프트를 고친다.** 놓친 것과 오탐 양쪽을 함께 줄일 수 있는 유일한 후보다. 입력과 추출을 바꾸지 않으므로 사실의 시점, 서로 다른 값, 원문 근거를 잃지 않는다.

M5에서 실패한 사실 줄이기(최근 순, 첫 값+최신 값, 글자 유사도)는 다시 하지 않는다. 앞 화 사실은 지금처럼 모두, 400개씩 넘긴다. 추출 누락 4개(retrieval)는 이번 단계에서 다루지 않는다. 다음 후보로 남긴다.

## 2. 가설과 바꿀 내용

**가설**: 모델에게 변화의 정당성을 판단하는 절차를 명시하면 다음 두 가지가 함께 준다.

- 설명이 없는 같은 속성의 값 차이를 놓치는 것
- 검사한 화 안에 설명이 있는 변화를 보고하는 것

후보 프롬프트 `detect-2`는 detect-1의 규칙 2를 아래 셋으로 바꾸거나 더한다. 문구는 구현 PR에서 확정하고 감독 검토를 받는다.

1. **설명 찾기**
   - 보고하기 전에, 검사 대상 화 전체와 참고 자료에서 그 차이를 설명하는 서술을 찾는다. 시간 경과, 성장·승급, 숨김·거짓말·변장, 가상현실·꿈·회상이 해당한다.
   - 본문이 그렇게 밝히면 보고하지 않는다.
   - 본문에 없는 설명을 짐작해 만들지 않는다.
2. **설명 없는 차이는 보고**
   - 같은 대상의 같은 속성 값이 다르고, 1의 설명이 본문에 없으면 시간이 흘렀으리라고 짐작하지 말고 보고한다.
   - 대상 속성은 이름·코드네임, 직책·소속, 학년·나이, 등급·서클, 수량이다.
3. **계산해서 비교**: 참고 자료의 비율이나 단위로 계산해야 하는 값은 계산해서 비교한다.

출력 형식(스키마)은 바꾸지 않는다. 따라서 저장 형식(ai.db)과 화면도 바뀌지 않는다. 별명·호칭, 회상, 유품 같은 기존 제외 규칙은 그대로 둔다.

## 3. 반례와 회귀 위험

- **2 때문에 오탐이 늘 수 있다.** 설명이 사실로 추출되지 않은 앞 화에 있으면 모델은 설명을 볼 수 없다. U01처럼 그 사이 성장이 있었던 경우다.
- **1 때문에 놓치는 것이 늘 수 있다.** 모델이 설명을 지어낼 수 있다. 예를 들어 S19의 "~라 알려진"을 소문이라 보고 넘어갈 수 있다. 그래서 "본문이 밝힌 설명만"을 명시한다.
- **20개 표본에 맞춘 프롬프트가 될 위험이 있다.** 규칙은 사례 이름이 아니라 일반 유형으로 쓴다. 합성 원고(M4)로 회귀를 따로 확인한다. 실제 원고의 별도 평가 묶음은 없다. 이 한계는 보고서에 밝힌다.
- **MIN_CONFIDENCE 0.7을 다시 확인해야 한다.** 이 기준은 luna와 detect-1에서 정했다. 프롬프트를 바꾸면 확신도 분포가 바뀔 수 있다.

## 4. 검증 (기준을 실행 전에 고정)

**입력은 M8과 똑같이 한다.**

- M8 복사본의 저장된 분석을 다시 추출하지 않고 그대로 쓴다. 같은 20화, luna, 400개씩 나눠 검사, 확신도 0.7.
- 호출 전에 화마다 넘기는 사실 수가 M8(25~4,513개)과 같은지 확인한다. 다르면 실행하지 않는다.
- retrieval은 입력이 같으므로 12/20 그대로다. 판단 단계만 비교한다.

**실행**

- 실제 원고: detect-2로 20화 검사를 2회 한다. 비교 기준은 M8의 detect-1 1회다. detect-1의 반복 편차는 재지 않는다. 이 한계는 보고서에 밝힌다.
- 합성 원고 회귀: M4의 15화(M0-A test)를 detect-2로 3회 검사한다.

| 기준 | 목표 |
|---|---|
| Recall (사람 판정, 0.7 적용 뒤) | 2회 모두 ≥ 10/20 (50%) |
| 기존에 찾던 9개 보존 | 2회 모두 8개 이상 |
| 근거가 있었던 12개 중 찾은 비율 (judge) | 5/12보다 높음 |
| 화당 오탐 (사람 판정, 판단 어려움 별도) | 2회 모두 ≤ 0.45 (M8보다 나빠지지 않음) |
| 검사한 화 안에 설명이 있던 오탐 3개 (U05, U06, U12) | 2회 중 1회 이상 사라짐 |
| 새로 생긴 정답표 밖 결과 | 모두 사람 판정 |
| 합성 원고 M4 | Recall ≥ 85%, Precision ≥ 85%, 화당 오탐 ≤ 0.3 (3회 모두. M4는 90%/100%/0) |
| 확신도 기준 0.7 | detect-2의 맞는 지적이 0.7 아래로 내려가지 않는지 확인 |
| 비용 | Costs API 차액 ≤ $1.2 |

**판정**

- 위 기준을 모두 충족할 때만 제품 프롬프트를 detect-2로 바꾼다. `DETECT_PROMPT_VERSION`을 올리고, 단위 테스트와 E2E를 확인한다.
- 하나라도 미달이면 제품을 바꾸지 않고 결과만 보고한다.
- S07·S11(모호한 근거)은 성패와 상관없이 따로 적는다.

## 5. 비용 계획

- **어림 (토큰 계산)**
  - 실제 원고 20화 검사는 M8에서 1회 $0.470이었다. 2회면 약 $0.94다.
  - 합성 15화 3회는 약 $0.05다.
  - 합계 약 $1.0. 상한은 $1.2로 두고 `withBudget`이 넘으면 멈추게 한다.
- **실비 (Costs API)**
  - 2026-10-26 00:01 KST 기준 누적 $6.8615다. 한도 $10에서 $3.1385가 남았다.
  - 실행 직전과 실행 뒤(반영 지연 후 다시)에 확인한다.
  - 실행 뒤 예상 잔액은 약 $2.1다.
- **이번 진단·계획 단계는 유료 호출 0회다.**

## 6. 순서

1. 이 진단·계획 PR을 감독 검토하고 병합한다.
2. 구현 PR을 올린다. 다음 셋으로 이루어진다.
   - 후보 프롬프트 detect-2를 측정 스크립트에서 고를 수 있게 한다. 제품의 기본값은 detect-1 그대로다.
   - 입력이 같은지 확인하는 단계를 둔다.
   - 단위 테스트를 더한다.
3. 감독 검토가 끝나면 4절의 실행을 한다. 비용을 확인한 뒤에 한다.
4. 결과 보고서를 쓴다. 기준을 충족하면 제품 기본값을 바꾸는 PR을 따로 올린다.
