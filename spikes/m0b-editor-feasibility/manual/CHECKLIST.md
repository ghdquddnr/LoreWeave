# M0-B 수동 검증 체크리스트

자동화할 수 없는 항목 (M0-PLAN §3 IME·Undo·붙여넣기 행, §1 렌더링 비교). 결과 칸에 `○` / `×` / 메모를 적거나, 채팅으로 알려 주면 REPORT에 옮긴다.

## 0. 준비

```bash
cd spikes/m0b-editor-feasibility
corepack pnpm dev          # 브라우저: Chrome에서 http://localhost:5173
corepack pnpm electron     # Electron 창 (dev 서버가 떠 있어야 함)
corepack pnpm corpus       # 렌더링 비교용 파일: out/corpus/<그룹>/<id>.md
```

- 입력기: Windows 기본 **Microsoft 한국어 IME** (두벌식). 다른 입력기를 쓰면 이름을 적는다.
- 변환기는 **(c) 직접 작성 · C3**를 고른다 (round-trip 100%). 다른 조합에서 문제가 보이면 함께 적는다.
- 데이터 손상 = 음절 중복·누락, 자모 분리(`ㅎ하`), 커서 튀기, 입력하지 않은 글자. 오타(내가 잘못 친 것)는 손상이 아니다.
- 문제를 찾으면: 페이지 상단 **IME 검사 모드**를 켠 상태에서 재현하고, 오른쪽 아래 "입력 이벤트" 내용을 복사해 둔다.

## 1. IME 시나리오

각 시나리오를 Chrome과 Electron에서 한 번씩. 빈 줄이나 아무 문단에서 해도 된다.

| # | 시나리오 | 방법 | 통과 기준 | Chrome | Electron | 메모 |
|---|---|---|---|---|---|---|
| 1 | 조합 중 Enter | `한` 조합 중(밑줄 상태) Enter | `한`이 확정되고 다음 줄로. 글자 중복·누락 없음 | | | |
| 2 | 조합 중 Backspace | `값` 조합 중 Backspace 두 번 | `가` → 빈칸 순으로 자모 단위 삭제 | | | |
| 3 | 줄 시작에서 조합 | 빈 줄 맨 앞에서 `안녕하세요` | 첫 음절 누락·중복 없음 | | | |
| 4 | 강조 끝에서 조합 | **굵은 글자** 바로 뒤에 커서 → `입니다` | 글자가 깨지지 않음 (굵게 이어지는지는 메모) | | | |
| 5 | 조합 직후 Undo | `안녕` 입력 후 바로 Ctrl+Z | 조합 단위 또는 어절 단위로 깔끔히 취소. 반쪽 자모가 남지 않음 | | | |
| 6 | 조합 중 Undo | `안녀` 조합 중 Ctrl+Z | 문서가 깨지지 않음 (동작은 메모) | | | |
| 7 | 선택 영역 덮어쓰기 | 단어 하나 선택 → `바꿈` 입력 | 선택이 지워지고 `바꿈`만 남음 | | | |
| 8 | 조합 중 방향키 | `한` 조합 중 → 키 | `한` 확정 후 커서 이동 | | | |
| 9 | 한자 변환 | `한자` 입력 후 한자 키 → 漢字 선택 | `漢字`로 바뀜, 앞뒤 글자 유지 | | | |
| 10 | 붙여넣기 직후 입력 | 텍스트 붙여넣기 → 바로 `가나다` | 붙여넣은 글자와 입력이 섞이지 않음 | | | |
| 11 | 조합 중 클릭 | `한` 조합 중 다른 문단 클릭 | `한`이 원래 자리에 확정됨 | | | |
| 12 | 빠른 연타 | `ㅋㅋㅋㅋ`, `아아아아` 빠르게 | 누락·중복 없음 | | | |

### 30분 연속 입력 (데이터 손상 0건 기준)

1. **IME 검사 모드**를 켜고 사례를 `m0a-ch03` 같은 M0-A 챕터로 고른다 (약 1,200자, 10분 안팎).
2. 왼쪽 원고를 에디터에 따라 친다. 오른쪽 아래에 원고와 다른 곳이 표시된다 (아직 치지 않은 부분도 차이로 나온다).
3. 다른 곳이 오타가 아니라 위 "데이터 손상"이면 이벤트 기록을 복사한다.
4. 챕터 2~3개로 합계 30분. Electron에서 최소 10분 포함.

## 2. Undo / Redo

| # | 항목 | 방법 | 통과 기준 | 결과 |
|---|---|---|---|---|
| 1 | 입력 Undo 단위 | 한 문장 입력 후 Ctrl+Z 반복 | 단위를 적는다 (어절 / 일정 시간 / 전체). 반쪽 자모 없음 | |
| 2 | Redo | Ctrl+Z 후 Ctrl+Y, Ctrl+Shift+Z | 둘 다 다시 실행됨 | |
| 3 | 파일 연 직후 Undo | 사례를 고른 직후 아무것도 안 하고 Ctrl+Z | **문서가 비거나 이전 사례로 돌아가지 않음** | |
| 4 | 붙여넣기 Undo | 긴 텍스트 붙여넣기 → Ctrl+Z 한 번 | 붙여넣기 전체가 한 번에 취소 | |
| 5 | 입력 직후 붙여넣기 Undo | 몇 글자 입력하고 0.5초 안에 붙여넣기 → Ctrl+Z | 결과를 적는다 (자동 측정에서는 앞의 입력까지 함께 취소됨: 히스토리가 500ms 안의 변경을 묶음) | |

## 3. 붙여넣기

빈 줄 하나 정도 있는 2~3문단 분량을 각 출처에서 복사해 에디터에 붙여넣고 "저장 결과" 패널을 본다.

| # | 출처 | 확인할 것 | 결과 |
|---|---|---|---|
| 1 | 메모장 (일반 텍스트) | 줄마다 문단으로 들어오는가, 빈 줄 유지 | |
| 2 | 웹페이지 (뉴스·블로그) | 글자 손실 없음, 링크·이미지·표 처리, 굵게 등 서식이 남는가 | |
| 3 | Word | 글자 손실 없음, 서식, 빈 줄 | |
| 4 | 한글(HWP) | 글자 손실 없음, 서식, 빈 줄 | |
| 5 | `*`·`_`·`[ ]`가 들어간 텍스트 | 저장 결과에서 글자 그대로인가 (이스케이프 `\*` 없음) | |
| 6 | 빈 줄이 여러 개 연속인 텍스트 | 빈 줄 수가 유지되는가 | |

서식이 남는 게 좋은지(굵게 유지) 지우는 게 좋은지는 의견을 메모로 남긴다.

## 4. 렌더링 비교 (빈 줄 규약)
